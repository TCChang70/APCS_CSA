## 暴力列舉三種寫法

### 寫法 1：巢狀迴圈列舉「兩兩組合」

```python
# 找「任兩個數相乘」的最大值（暴力 O(N²)：雙層迴圈把所有組合都試過）
a = [3, 1, 4, 2]
best = -10**18                       # 答案先設成極小值，保證會被更新
for i in range(len(a)):              # 外層選「第一個數」a[i]
    for j in range(i + 1, len(a)):   # 內層從 i+1 開始：j 永遠大於 i
        # 好處①：不會算到自己（a[i]*a[i]）
        # 好處②：組合只算一次（(i,j) 不會和 (j,i) 重複）→ 省一半時間
        best = max(best, a[i] * a[j])   # 每次找到更大的就更新
print(best)
```

| 重點 | 說明 |
| --- | --- |
| `range(i + 1, ...)` | 只列舉「組合」（不考慮順序），省一半且不會算到 (i,i) |

### 寫法 2：巢狀迴圈列舉「所有點對」

```python
# 平面上 n 個點，找「距離最近」的一對（暴力 O(N²)）
pts = [list(map(int, input().split())) for _ in range(n)]   # 逐點讀入座標 (x, y)
best = 10**18                       # 求「最小」距離，初始設成極大值
for i in range(n):                  # 第一個點
    for j in range(i + 1, n):       # 第二個點從 i+1 開始（避免自己、避免重複）
        # 用「距離平方」比較即可，不必開根號（大小順序不變，還更快）
        d2 = (pts[i][0] - pts[j][0])**2 + (pts[i][1] - pts[j][1])**2
        best = min(best, d2)        # 若這對更近就更新
```

### 寫法 3：遞迴枚舉「選／不選」

> 每個元素「要不要」都試一遍。常用在子集合、分割類問題。

```python
a = [2, 3, 7]
def dfs(idx, cur_sum):       # 現在要決定第 idx 個元素，目前累積和是 cur_sum
    if idx == len(a):        # 終止條件：全部元素都決定完了
        print(cur_sum)       # 印出這條路徑的總和
        return               # 一定要 return，否則繼續往下會超界
    dfs(idx + 1, cur_sum)            # 分支①「不選」a[idx]：累積和不變，處理下一個
    dfs(idx + 1, cur_sum + a[idx])   # 分支②「選」a[idx]：累積和加上它，處理下一個

dfs(0, 0)    # 從第 0 個元素開始，累積和 0
# 每個元素都有「選/不選」兩種 → 共 2^3 = 8 種組合，會印出所有可能的子集合和
```

| 參數 | 意義 |
| --- | --- |
| `idx` | 現在處理到第幾個元素 |
| `cur_sum` | 目前累積的和 |
| 兩個分支 | 「不選」與「選」各走一步 |

> 注意：這種窮舉是 2^N 種，n 只能很小（≤ 20 左右）。

## 二分搜尋：在排序資料中找東西

二分 = 每次砍掉一半。前提：資料**有序**（或「答案單調」）。

```python
def binary_search(arr, target):    # 在「已排序」的 arr 裡找 target，回傳索引
    l, r = 0, len(arr) - 1         # 目前搜尋範圍：從第一個到最後一個
    while l <= r:                  # 範圍還沒空（l、r 未交錯）就繼續
        mid = (l + r) // 2         # 取正中間的位置
        if arr[mid] == target:     # 剛好就是目標
            return mid             # 回傳索引
        elif arr[mid] < target:    # 中間值「太小」→ 目標一定在右半邊
            l = mid + 1            # 把左界移到 mid 右邊一格
        else:                      # 中間值「太大」→ 目標一定在左半邊
            r = mid - 1            # 把右界移到 mid 左邊一格
    return -1                      # 迴圈結束還沒找到 → 回傳 -1（找不到）
# 每次砍掉一半 → 時間複雜度 O(log N)，N 到 10^18 都只要約 60 步
```

| 變數 | 意義 |
| --- | --- |
| `l, r` | 目前搜尋範圍的左右界 |
| `mid = (l + r) // 2` | 正中間 |
| `arr[mid] < target` | 中間太小 → 答案一定在右邊 |

### 二分搜「答案」（重要！）

很多題目不是找「某個數」，而是找「最小/最大的可行答案」。模板長這樣：

```python
def can(mid):       # 判斷「答案 = mid 是否可行」，由你依題目實作
    ...

l, r = 0, 10**18    # 答案範圍下界、上界（視題目而定，此處為示意）
while l < r:        # 二分：當左右界還沒收斂到同一點就繼續
    mid = (l + r) // 2       # 猜中間值
    if can(mid):    # 可行 → 試「更小」的答案
        r = mid    # 右界縮到 mid（mid 本身仍是可行答案，保留）
    else:           # 不可行 → 答案「必須更大」
        l = mid + 1    # 左界移到 mid 右邊一格
print(l)            # 迴圈結束 l == r，就是「最小的可行答案」
# 記憶口訣（找最小可行答案）：可行 → r=mid；不可行 → l=mid+1
```

> 關鍵：`can(mid)` 一定要「單調」——答案越大越容易（或越小越容易），二分才有意義。

### 「最小化最大值」題型

題目出現：「把 n 個東西分成 k 組，讓**每組和的最大值最小**」→ 幾乎都是二分＋can。

```python
def can(mid):              # 驗證：「讓每組總和 ≤ mid」時，最少要分幾組
    groups, cur = 1, 0     # 已開的組數（從 1 組開始）、目前這一組已累積的和
    for x in a:            # 依序放每個數字
        if cur + x > mid:  # 把 x 塞進這組會「超過上限」→ 塞不下
            groups += 1    # 開一組新的
            cur = x        # 新組目前就裝 x 一個
        else:
            cur += x       # 塞得下 → 放進目前這組
    return groups <= k     # 用 ≤ k 組就裝得下 → mid 是「可行」答案
```

| 部分 | 意義 |
| --- | --- |
| `mid` | 我們猜的「每組最大總和上限」 |
| 掃描 | 貪心地塞，塞不下就開新組 |
| `groups <= k` | 用 ≤ k 組就裝得下 → 可行 |

## 範例逐行拆解

### 範例 1：雷射測試（ZJ i401，2022/6 第 3 題）概念

> 二分搜答案：猜一個「能量值 mid」，用 `can(mid)` 檢查這個能量能不能讓雷射打到目標。能量越大越容易 → 單調 → 二分。

### 範例 2：二分＋驗證完整範例

> 題目：n 個數字排成一列，要切成 k 段，每段的「和」都要 ≤ mid，求最小的 mid。正是「最小化最大值」。

```python
n, k = map(int, input().split())   # n 個數字、切成 k 段
a = list(map(int, input().split()))   # 讀入 n 個數字

def can(mid):                      # 行1：驗證「每段總和都 ≤ mid」是否辦得到
    groups, cur = 1, 0             #     已切段數、目前段累積和
    for x in a:                    #     貪心地依序分組
        if cur + x > mid:          # 行2：這格放進目前段會超過上限 → 開新段
            groups += 1
            cur = x                #     新段從這格開始
        else:
            cur += x               #     塞得下就累加進目前段
    return groups <= k             # 行3：只要 ≤ k 段就裝完 → mid 可行

l, r = max(a), sum(a)              # 行4：答案下界 = 單一最大值（最大那格至少獨自一段）
                                   #      上界 = 全部總和（整列當成一段）
while l < r:                       # 行5：標準二分
    mid = (l + r) // 2
    if can(mid):                   # 行6：可行 → 試試更小的答案
        r = mid
    else:                          # 行7：不可行 → 答案必須更大
        l = mid + 1
print(l)                           # 行8：l == r，就是最小的可行答案
```

| 行 | 意義 |
| --- | --- |
| 1 | 定義驗證函式 |
| 2 | 塞不進去就另起一段（貪心） |
| 3 | 用 ≤ k 段就達成 |
| 4 | 答案下界 = 最大值（單一元素也得放），上界 = 總和（整列一段） |
| 5～7 | 標準「找最小可行答案」二分 |
| 8 | 答案就是 l |

> 練習法：把「l, r 的邊界為何這樣設」想清楚。下界設成 `max(a)` 可加速，但不能設太小否則答案不可能。

## 常見錯誤檢查表

| # | 錯誤 | 為什麼錯 | 修正 |
| --- | --- | --- | --- |
| 1 | 二分條件搞反（該 r=mid 卻 l=mid+1） | 找最大/最小混用 | 先確定「答案單調方向」 |
| 2 | `while l < r` 配 `mid = (l+r)//2` 卡死 | 更新寫成 `l = mid` 時可能不動 | 找最小答案用 `l = mid + 1` |
| 3 | `can(mid)` 不是單調 | 二分失去根據 | 改暴力或換做法 |
| 4 | 組合列舉沒從 `i+1` 開始 | 重複算、(i,i) 自乘 | `for j in range(i+1, n)` |
| 5 | 遞迴枚舉忘了「終止條件」 | 無限遞迴當掉 | 第一個 if 一定要有 `return` |
| 6 | 二分範圍開太大導致 can 太慢 | TLE | can 要 O(N)，二分才划算 |
| 7 | 暴力寫完就滿足 | 大測資全掛 | 一定要再想優化 |

```python
# 題2：任兩數差的「最小值」（排序即可，O(N log N)，比暴力 O(N²) 快）
n = int(input())
a = list(map(int, input().split()))   # 讀入 n 個數字
a.sort()                              # 排序：最小差距一定出現在「相鄰」兩數之間
# 逐一算相鄰差距，min() 取最小
print(min(a[i + 1] - a[i] for i in range(n - 1)))
```
