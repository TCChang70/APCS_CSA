## 什麼是遞迴？

**遞迴（Recursion）** 是指一個函式呼叫自身來解決問題的方法。

核心思想：**將原問題分解為一個或多個規模更小的相同問題**，直到問題簡單到可以直接解決（基底條件）。

```
f(n) = f(n-1) + f(n-2)   ← 遞迴關係
f(0) = 0, f(1) = 1        ← 基底條件
```

---

## 遞迴三要素

| 要素 | 說明 | 錯誤範例 |
|------|------|----------|
| **1. 基底條件（Base Case）** | 最簡單的情況，直接回傳結果而不呼叫自身 | 缺少 → 無窮遞迴 → Stack Overflow |
| **2. 遞迴關係（Recurrence）** | 將問題拆解成更小的子問題 | 子問題沒變小 → 無窮遞迴 |
| **3. 收斂性（Convergence）** | 每次呼叫都要朝基底條件靠近 | 參數沒變化 → 無窮遞迴 |

## 中階遞迴進階主題

### 6. 樹狀結構遞迴

樹是天然的遞迴資料結構：每個節點的子樹就是一棵更小的樹。

```
前序（Pre-order）：  root → 左子樹 → 右子樹
中序（In-order）：   左子樹 → root → 右子樹
後序（Post-order）：  左子樹 → 右子樹 → root
```

### 7. Backtracking 剪枝

在遞迴窮舉時，若當前分支**不可能**導向合法解，就直接放棄（剪枝），
可大幅減少搜尋空間。

### 8. 尾遞迴（Tail Recursion）

若遞迴呼叫是函式最後一個動作（且回傳值直接回傳），稱為尾遞迴。
某些語言可優化為迴圈（TCO），但 Python **不支援**尾遞迴優化。

```
def tail_factorial(n, acc=1):    ← acc 是累積器
    if n == 0: return acc
    return tail_factorial(n-1, n*acc)  ← 最後一個動作就是呼叫自身
```

### 9. Divide and Conquer（分治法）

1. **Divide**：將問題切成數個小問題
2. **Conquer**：遞迴解決每個小問題
3. **Combine**：合併子問題的結果

### 10. 遞迴與 Stack 的關係

每次遞迴呼叫，系統會在 Call Stack 上壓入一個**堆疊幀**（Stack Frame），
包含區域變數、返回位置等。遞迴返回時再 Pop。

```
遞迴深度 = Call Stack 同時存在的幀數
Python 預設上限：1000（可用 sys.setrecursionlimit() 調整）
```

## 遞迴 vs 迴圈

| 比較 | 遞迴 | 迴圈 |
|------|------|------|
| 程式碼 | 簡潔、接近數學定義 | 通常較長 |
| 可讀性 | 高（對於遞迴思維熟練者） | 高（對於一般人） |
| 記憶體 | 每個呼叫佔用 stack 空間 | 通常 O(1) |
| 效能 | 函式呼叫有開銷 | 較快 |
| 適合場景 | 樹、圖、分治、回溯 | 單純重複操作 |

## 遞迴深度估算技巧

APCS 實作題中，有時需要估算遞迴深度以決定是否改用迭代。

| 輸入大小 N | 遞迴深度 | 是否安全 |
|-----------|---------|---------|
| N ≤ 30    | ≤ 30 層 | ✓ Python 預設 1000，安全 |
| N ≤ 500   | ≤ 500 層 | ✓ 安全 |
| N ≤ 2000  | ≤ 2000 層 | ⚠ 需 `setrecursionlimit(10000)` |
| N ≤ 10⁵   | 可能 10⁵ 層 | ✗ 必須改用迭代或 BFS |

**快速判斷**：若遞迴深度約等於 N（如費氏、河內塔），
則 N ≤ 10³ 可用遞迴，N > 10³ 建議改迭代。

## 中階遞迴設計模式

### 模式一：累積器傳遞（Accumulator Pattern）
適用於尾遞迴優化：
```python
def sum_list(lst, acc=0):
    if not lst: return acc
    return sum_list(lst[1:], acc + lst[0])
```

### 模式二：Helper Function（包裹函式）
外部函式負責初始化，內部 helper 做實際遞迴：
```python
def factorial(n):
    def helper(k, acc):
        if k == 0: return acc
        return helper(k - 1, k * acc)
    return helper(n, 1)
```

### 模式三：Backtracking 標準模板
```python
def solve():
    def backtrack(選擇列表, 路徑):
        if 滿足條件:      # 基底
            記錄答案
            return
        for 選擇 in 選擇列表:
            做選擇          # 前序
            backtrack(...) # 遞迴
            撤銷選擇        # 後序（回溯）
    backtrack(...)
```

## APCS 遞迴題型辨識指南

看到題目時，可用以下流程判斷是否該用遞迴：

```
問題可以分解成更小的相同問題嗎？
  ├── 否 → 用迴圈或條件判斷
  └── 是 → 問題有重疊子問題嗎？
       ├── 是 → DP（遞迴 + 記憶化）
       └── 否 → 問題結構是樹狀或巢狀嗎？
            ├── 是 → 樹遞迴 / DFS
            └── 否 → 需要窮舉所有可能性嗎？
                 ├── 是 → Backtracking
                 └── 否 → 簡單遞迴
```

> **APCS 實戰建議**：若遞迴深度可能很大（如 N > 1000），Python 的遞迴深度限制預設為 1000，需用 `sys.setrecursionlimit()` 調整或用迴圈替代。

## 常見錯誤與陷阱

1. **忘記基底條件** → 無窮遞迴 → RecursionError
2. **基底條件永遠不會達到** → 參數沒正確變化
3. **重複計算** → 如樸素費氏數列，指數爆炸（O(2ⁿ)）
4. **遞迴深度過大** → Python 預設上限 1000
5. **可變物件作為預設參數** → `def f(x, lst=[])` 會共用同一個 list

---

## 實戰建議

1. **先寫基底條件**：再寫遞迴關係
2. **畫遞迴樹**：幫助理解呼叫過程
3. **確認收斂**：參數是否每次都在縮小
4. **考慮深度**：APCS 實作題若遞迴層級可能很深，優先考慮 memoization 或改迭代
5. **背模板**：Backtracking、DFS 有固定寫法，熟練可加快答題速度
6. **樹狀問題用遞迴**：遇到樹、目錄結構、JSON 巢狀資料，優先想遞迴
7. **剪枝放前面**：Backtracking 先檢查不可能的分支再遞迴，效能可差好幾個數量級
8. **先暴力再優化**：APCS 實戰中，先寫出樸素遞迴拿到部分分，再補 memoization
