# 動態規劃學習內容：ex1 ~ ex5（優化版）

> 動態規劃（Dynamic Programming，DP）是把一個大問題分成很多小問題，
> 並把這些小問題的答案記錄下來，不重複計算，最終組合出整體解答的技術。

---

## 動態規劃的核心三要素

| 要素 | 說明 | 範例（爬樓梯） |
|------|------|----------------|
| **狀態定義** | `dp[i]` 代表什麼意思？ | dp[i] = 到第 i 階的方法數 |
| **狀態轉移方程式（Transition）** | 如何從已知的 `dp` 值推出下一個？ | dp[i] = dp[i-1] + dp[i-2] |
| **初始值（Base Case）** | 最小的問題答案是多少？ | dp[1]=1, dp[2]=2 |

> 只要能清楚定義這三個部分，就能解出大多數 DP 題型。

### 解題前先問自己四個問題

| # | 問題 | 用意 |
|---|------|------|
| 1 | dp[i] 代表什麼？ | 定義狀態 |
| 2 | dp[i] 怎麼從前面算出來？ | 找轉移方程式 |
| 3 | dp[0]、dp[1] 是多少？ | 設定初始值 |
| 4 | 迴圈從哪裡跑到哪裡？ | 確定計算順序 |

## 1. ex1_爬樓梯與零錢.py

### 1-1 這支程式在做什麼？

這支程式展示兩個最基礎的一維 DP（1D DP）：

- **爬樓梯**：一次爬 1 階或 2 階，到第 `n` 階共有幾種走法？
- **零錢問題（Coin Change）**：給定幾種硬幣面額，湊出目標金額的最少硬幣數量

---

### 1-2 爬樓梯 — 概念與狀態分析

$$dp[i] = dp[i-1] + dp[i-2]$$

**白話解釋**：到第 `i` 階的方法數 = 從第 `i-1` 階走 1 步的方法數 + 從第 `i-2` 階走 2 步的方法數。

#### 狀態定義表

| 項目 | 內容 |
|------|------|
| 狀態 | dp[i] = 到第 i 階的方法數 |
| 轉移 | dp[i] = dp[i-1] + dp[i-2] |
| 初始 | dp[1]=1, dp[2]=2 |
| 答案 | dp[n] |

#### 狀態依賴圖

```
dp[i] 依賴哪兩個？
  dp[i-2]  ──┐
             ├──>  dp[i] = dp[i-1] + dp[i-2]
  dp[i-1]  ──┘

  第 i 階 = 從第 i-1 階走 1 步 + 從第 i-2 階走 2 步
```

#### 程式碼解析

```python
def climb_stairs(n):
    if n <= 2:
        return n
    a, b = 1, 2
    for _ in range(3, n + 1):
        a, b = b, a + b
    return b
```

**滾動變數（Rolling Variables）**：dp[i] 只依賴 dp[i-1] 和 dp[i-2]，不需要保留整個陣列，空間 O(N) → O(1)。

#### 執行流程追蹤表（`n = 6`）

| 迴圈次數 i | 更新前 a, b | 計算 a+b | 更新後 a, b | 對應 dp[i] |
|-----------|-------------|----------|-------------|------------|
| 初始 | 1, 2 | — | 1, 2 | dp[1]=1, dp[2]=2 |
| 1（i=3） | 1, 2 | 1+2=3 | **2, 3** | dp[3]=3 |
| 2（i=4） | 2, 3 | 2+3=5 | **3, 5** | dp[4]=5 |
| 3（i=5） | 3, 5 | 3+5=8 | **5, 8** | dp[5]=8 |
| 4（i=6） | 5, 8 | 5+8=13 | **8, 13** | dp[6]=13 |

#### 手動列舉驗證（`n=4`）

```text
1-1-1-1
1-1-2
1-2-1
2-1-1
2-2
共 5 種 ✓
```

#### 陣列版 vs 滾動變數版對比

| 比較 | 陣列版 | 滾動變數版 |
|------|--------|-----------|
| 空間 | O(N) | **O(1)** |
| 程式碼 | 需要 dp = [0]*(n+1) | 只需 a, b 兩個變數 |
| 可讀性 | 較直覺 | 需理解「a 代表 dp[i-2], b 代表 dp[i-1]」 |

### 1-3 零錢問題 — 概念與狀態分析

$$dp[amt] = \min_{c \in coins}(dp[amt - c] + 1)$$

**白話解釋**：湊出金額 `amt` 的最少硬幣數 = 先湊出 `amt - c` 元（已知最優解），再加一枚 `c` 元硬幣，對所有硬幣面額取最小。

#### 狀態定義表

| 項目 | 內容 |
|------|------|
| 狀態 | dp[x] = 湊出金額 x 的最少硬幣數 |
| 轉移 | dp[x] = min(dp[x-c] + 1) for c in coins |
| 初始 | dp[0]=0，其餘 INF |
| 答案 | dp[amount]（若為 INF 回傳 -1） |

#### 程式碼解析

```python
def coin_change(coins, amount):
    INF = 10 ** 9
    dp = [INF] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for c in coins:
            if i >= c:
                dp[i] = min(dp[i], dp[i - c] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

| 變數 | 意義 |
|------|------|
| `INF = 10**9` | 代表「還不知道怎麼湊」，讓 min 判斷有效 |
| `dp[0] = 0` | 湊 0 元不需要任何硬幣，是初始值 |
| 內層 `for c in coins` | 對每個金額，嘗試所有硬幣面額 |
| `if i >= c` | 面額不能大於金額 |
| 最後 `!= INF` | 有解才回傳，否則 -1 |

#### 執行流程追蹤表（硬幣 `[1, 2, 5]`，金額 `11`）

| 金額 i | c=1 嘗試 | c=2 嘗試 | c=5 嘗試 | dp[i] 最終值 | 湊法 |
|--------|----------|----------|----------|--------------|------|
| 0 | — | — | — | **0** | 不用硬幣 |
| 1 | dp[0]+1=1 | — | — | **1** | 1 |
| 2 | dp[1]+1=2 | dp[0]+1=1 | — | **1** | 2 |
| 3 | dp[2]+1=2 | dp[1]+1=2 | — | **2** | 2+1 |
| 4 | dp[3]+1=3 | dp[2]+1=2 | — | **2** | 2+2 |
| 5 | dp[4]+1=3 | dp[3]+1=3 | dp[0]+1=1 | **1** | 5 |
| 6 | dp[5]+1=2 | dp[4]+1=3 | dp[1]+1=2 | **2** | 5+1 |
| 7 | dp[6]+1=3 | dp[5]+1=2 | dp[2]+1=2 | **2** | 5+2 |
| 8 | dp[7]+1=3 | dp[6]+1=3 | dp[3]+1=3 | **3** | 5+2+1 |
| 9 | dp[8]+1=4 | dp[7]+1=3 | dp[4]+1=3 | **3** | 5+2+2 |
| 10 | dp[9]+1=4 | dp[8]+1=4 | dp[5]+1=2 | **2** | 5+5 |
| 11 | dp[10]+1=3 | dp[9]+1=4 | dp[6]+1=3 | **3** | 5+5+1 |

答案：`3`（5 + 5 + 1）

#### 為什麼初始值用 INF 而不是 0？

```
如果初始值設為 0：
  dp[1] = min(0, dp[0]+1) = 0    ← 永遠都是 0，答案錯誤！
  → min 判斷「失效」，所有金額都會算出 0

如果初始值設為 INF：
  dp[1] = min(INF, 0+1) = 1      ← min 正常運作
  → 只有「真的算出解」才會更新
```

### 1-4 常見錯誤

❌ 忘記初始化 `dp[0] = 0`，導致所有值都是 `INF`
```python
dp = [INF] * (amount + 1)
# 忘記寫 dp[0] = 0 → 全部永遠是 INF，回傳 -1
```

✅ `dp[0]` 是基底條件，代表「湊出 0 元的最少硬幣數 = 0」，一定要設定

### 1-5 執行結果
```text
爬 10 階樓梯: 89 種方法
湊 11 元（硬幣 1,2,5）: 3 個硬幣
```

## 2. ex2_Kadane演算法.py

### 2-1 這支程式在做什麼？

**最大連續子陣列和（Maximum Subarray）**：給定一個整數陣列，找出總和最大的連續子陣列。

這是 APCS 中級最常考的 DP 題型之一，Kadane 演算法只需要一次遍歷（O(N)）就能解出。

### 2-2 核心觀念

$$dp[i] = \max(nums[i],\ dp[i-1] + nums[i])$$

**白話解釋**：以 `nums[i]` 結尾的最大子陣列和，有兩種選擇：
1. 延續前面的子陣列（`dp[i-1] + nums[i]`）
2. 從 `nums[i]` 重新開始（`nums[i]`）

取兩者的最大值就是 `dp[i]`。

#### 決策表：「重新開始」還是「接在後面」？

| 條件 | 決策 | 原因 |
|------|------|------|
| nums[i] > dp[i-1] + nums[i] | 從 nums[i] **重新開始** | 前面的子陣列和是負的，是負擔 |
| nums[i] <= dp[i-1] + nums[i] | **接在後面**繼續延伸 | 前面的子陣列能加分 |

#### 狀態定義表

| 項目 | 內容 |
|------|------|
| 狀態 | dp[i] = 以位置 i 結尾的最大子陣列和 |
| 轉移 | dp[i] = max(nums[i], dp[i-1] + nums[i]) |
| 初始 | dp[0] = nums[0] |
| 答案 | max(dp[0], ..., dp[n-1]) |

### 2-3 程式碼解析

```python
def max_subarray(nums):
    cur = best = nums[0]
    for v in nums[1:]:
        cur = max(v, cur + v)
        best = max(best, cur)
    return best
```

| 變數 | 意義 |
|------|------|
| `cur` | 以當前位置結尾的最大子陣列和（對應 dp[i]） |
| `best` | 全局目前的最大值（對應 max(dp)） |

這個版本用滾動變數，空間複雜度是 O(1)。

### 2-4 執行流程追蹤表

陣列：`[-2, 1, -3, 4, -1, 2, 1, -5, 4]`

| 索引 i | 值 v | cur+v（延續） | 決策 | cur（以此結尾最大和） | best（全局最大） |
|--------|------|---------------|------|------------------------|------------------|
| 0 | -2 | — | 起點 | **-2** | -2 |
| 1 | 1 | -2+1=-1 | 重開(1>-1) | **1** | 1 |
| 2 | -3 | 1+(-3)=-2 | 接(-2>-3) | **-2** | 1 |
| 3 | 4 | -2+4=2 | 重開(4>2) | **4** | 4 |
| 4 | -1 | 4+(-1)=3 | 接(3>-1) | **3** | 4 |
| 5 | 2 | 3+2=5 | 接 | **5** | 5 |
| 6 | 1 | 5+1=6 | 接 | **6** | **6** |
| 7 | -5 | 6+(-5)=1 | 接 | **1** | 6 |
| 8 | 4 | 1+4=5 | 接 | **5** | 6 |

最大子陣列和為 **6**，對應子陣列 `[4, -1, 2, 1]`。

#### 核心轉移視覺化

```
遇到 v=4（索引3）：
  cur=-2（前面的累積是 -2）

  「接在後面」：-2 + 4 = 2
  「自己重開」：4
  → 4 > 2，所以「自己重開」！前面 -2,1,-3 全部拋棄

  這是 Kadane 的靈魂：前面的和是負的，不如丟掉重新開始
```

### 2-5 帶索引版本解析

```python
def max_subarray_with_indices(nums):
    cur = best = nums[0]
    start = end = 0
    temp_start = 0
    for i, v in enumerate(nums[1:], 1):
        if v > cur + v:
            cur = v
            temp_start = i       # 重新開始，記錄新的起始點
        else:
            cur = cur + v
        if cur > best:
            best = cur
            start = temp_start   # 更新最佳解的起點
            end = i
    return best, start, end
```

#### 兩個起點變數的職責

| 變數 | 職責 |
|------|------|
| `temp_start` | 「當前正在延伸的子陣列」的暫定起點，每次重開就更新 |
| `start` | 「歷史最佳子陣列」的起點，只有破紀錄時才更新 |

```
決策「重開」時 → 只更新 temp_start（候選起點）
決策「破紀錄」時 → 才把 temp_start 確認為 start（正式起點）
```

### 2-6 常見錯誤

❌ 初始值設為 0，在全負數陣列時會得到錯誤答案
```python
cur = best = 0  # 若陣列全為負數，會回傳 0（不合理，應為最大負數）
```
✅ 應從 `nums[0]` 開始，確保至少選一個元素

### 2-7 執行結果
```text
最大子陣列和: 6
最大子陣列: [4, -1, 2, 1], 和 = 6
```

## 3. ex3_背包問題.py

### 3-1 這支程式在做什麼？

**0/1 背包問題（0/1 Knapsack）**：有 N 個物品，每件有重量和價值，背包最多能承載 W 公斤，每件物品最多拿一次，如何選物品使總價值最大？

另外也包含**無限背包（Unbounded Knapsack）**，每種物品可以取無限次。

### 3-2 核心觀念

#### 先看 2D 版（最容易理解）

$$dp[i][w] = \max(dp[i-1][w],\ dp[i-1][w - weight[i]] + value[i])$$

**白話解釋**：考慮「前 i 個物品、容量 w」時，有兩種選擇：
- **不拿第 i 件**：直接沿用「前 i-1 件、容量 w」的答案
- **拿第 i 件**：空出 weight[i] 的空間，加上前 i-1 件、容量 w-weight[i] 的答案

#### 狀態定義表

| 項目 | 內容 |
|------|------|
| 狀態 | dp[w] = 容量為 w 時的最大價值 |
| 轉移 | dp[w] = max(dp[w], dp[w-weight[i]] + value[i]) |
| 初始 | 全部 0 |
| 答案 | dp[W] |
| 迴圈方向 | **從後往前**（0/1 背包） |

#### 重要細節：為何從後往前更新？

在一維陣列的版本中，若從前往後更新，同一件物品可能被選多次（變成無限背包）。
從後往前更新能保證每件物品只被選一次。

```
倒序更新（0/1 背包）：
  容量:  0  1  2  3  4  5
              ← 從後往前更新
  先算 dp[5]，此時 dp[2]、dp[3] 還是「不含本件物品」的舊值
  → 每件物品最多被選一次 ✓

正序更新（無限背包）：
  容量:  0  1  2  3  4  5
              → 從前往後更新
  先算 dp[2]，再算 dp[4] 時 dp[2] 已是「含本件物品」的新值
  → 同一件物品可被重複選取（無限背包）✓
```

#### 正序 vs 倒序對照表

| 比較項目 | 0/1 背包 | 無限背包 |
|----------|----------|----------|
| 物品限制 | 每個最多選 1 次 | 每個可選無限次 |
| 迴圈方向 | **倒序** `range(W, wi-1, -1)` | **正序** `range(wi, W+1)` |
| 原因 | 用上一輪舊值，不重複 | 用本輪新值，可重複 |

### 3-3 程式碼解析

```python
def knapsack(weights, values, W):
    N = len(weights)
    dp = [0] * (W + 1)
    for i in range(N):
        for w in range(W, weights[i] - 1, -1):   # 從後往前
            dp[w] = max(dp[w], dp[w - weights[i]] + values[i])
    return dp[W]
```

### 3-4 執行流程追蹤表

物品：重量 `[2, 3, 4, 5]`，價值 `[3, 4, 5, 6]`，背包容量 `W = 5`

| 階段 | dp[0] | dp[1] | dp[2] | dp[3] | dp[4] | dp[5] |
|------|-------|-------|-------|-------|-------|-------|
| 初始 | 0 | 0 | 0 | 0 | 0 | 0 |
| 處理物品0（w=2,v=3）後 | 0 | 0 | **3** | **3** | **3** | **3** |
| 處理物品1（w=3,v=4）後 | 0 | 0 | 3 | **4** | **4** | **7** |
| 處理物品2（w=4,v=5）後 | 0 | 0 | 3 | 4 | **5** | **7** |
| 處理物品3（w=5,v=6）後 | 0 | 0 | 3 | 4 | 5 | **7** |

答案：`dp[5] = 7`（選物品0 w=2 v=3 + 物品1 w=3 v=4）

#### 物品1 的詳細計算過程（倒序）

| w | dp[w] 舊值 | dp[w-w1]+v1 = dp[w-3]+4 | max 結果 | dp[w] 新值 |
|---|-----------|--------------------------|----------|------------|
| 5 | 3 | dp[2]+4 = 3+4 = 7 | max(3,7) | **7** |
| 4 | 3 | dp[1]+4 = 0+4 = 4 | max(3,4) | **4** |
| 3 | 3 | dp[0]+4 = 0+4 = 4 | max(3,4) | **4** |
| 2 | 3 | w < w1=3，跳過 | — | 3 |

### 3-5 無限背包對比

```python
def knapsack_unbounded(weights, values, W):
    dp = [0] * (W + 1)
    for w in range(1, W + 1):
        for i in range(len(weights)):
            if w >= weights[i]:
                dp[w] = max(dp[w], dp[w - weights[i]] + values[i])
    return dp[W]
```

差異：無限背包的迴圈順序是**從前往後**，允許同一件物品被多次選取。

#### 為什麼正序就是無限背包？

```
假設物品 w=2, v=3，容量 5

正序更新：
  w=2: dp[2] = max(0, dp[0]+3) = 3    ← 第一次選
  w=4: dp[4] = max(0, dp[2]+3) = 6    ← dp[2] 已含物品，等於選了兩次！
  → 同一物品可無限次選取
```

### 3-6 常見錯誤

❌ 0/1 背包用從前往後的迴圈
```python
for w in range(weights[i], W + 1):  # 錯誤，同一件物品可重複選
    dp[w] = max(dp[w], dp[w - weights[i]] + values[i])
```
✅ 0/1 背包必須從後往前；無限背包才從前往後

### 3-7 執行結果
```text
0/1 背包容量 5: 7
無限背包容量 5: 7
```

## 4. ex4_最長遞增子序列.py

### 4-1 這支程式在做什麼？

**最長遞增子序列（LIS，Longest Increasing Subsequence）**：找出一個整數陣列中最長的嚴格遞增子序列，子序列不需要連續。

這支程式提供兩種解法：
- DP 解法：O(N²)，直覺易懂
- 貪婪 + 二分搜尋（Binary Search）解法：O(N log N)，效率更高

### 4-2 DP 解法（O(N²)）

$$dp[i] = \max_{j < i,\ nums[j] < nums[i]}(dp[j] + 1)$$

**白話解釋**：以 `nums[i]` 結尾的 LIS 長度 = 所有比 `nums[i]` 小的前面元素 `nums[j]` 的 LIS 長度 + 1，取最大值。

#### 狀態定義表

| 項目 | 內容 |
|------|------|
| 狀態 | dp[i] = 以 nums[i] 結尾的 LIS 長度 |
| 轉移 | dp[i] = max(dp[j]+1) for j<i 且 nums[j]<nums[i] |
| 初始 | dp[i] = 1（每個元素自己就是長度 1） |
| 答案 | max(dp) |

#### 程式碼解析
```python
def lis_dp(nums):
    n = len(nums)
    dp = [1] * n     # 每個元素自己就是長度 1 的子序列
    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)
```

#### 執行流程追蹤表

陣列：`[10, 9, 2, 5, 3, 7, 101, 18]`

| i | nums[i] | 檢查 j | 誰能接？（nums[j]<nums[i]） | dp[i] 更新過程 | dp[i] |
|---|---------|--------|----------------------------|----------------|-------|
| 0 | 10 | 無 | 無 | dp[0]=1 | **1** |
| 1 | 9 | j=0 | 10<9? 否 | dp[1]=1 | **1** |
| 2 | 2 | j=0,1 | 10<2? 否, 9<2? 否 | dp[2]=1 | **1** |
| 3 | 5 | j=0,1,2 | 2<5 ✓ | dp[3]=max(1, dp[2]+1=2) | **2** |
| 4 | 3 | j=0..3 | 2<3 ✓ | dp[4]=max(1, dp[2]+1=2) | **2** |
| 5 | 7 | j=0..4 | 2<7, 5<7, 3<7 | max(1, dp[2]+1=2, dp[3]+1=3, dp[4]+1=3) | **3** |
| 6 | 101 | j=0..5 | 全部<101 | max(1, ..., dp[5]+1=4) | **4** |
| 7 | 18 | j=0..6 | 2,5,3,7 <18 | max(1, dp[5]+1=4, ...) | **4** |

答案：`max(dp) = 4`

最長遞增子序列為 `[2, 3, 7, 18]` 或 `[2, 5, 7, 101]` 等，長度 **4**。

### 4-3 貪婪 + 二分搜尋解法（O(N log N)）

用 `tails` 陣列維護一個特殊的輔助序列：`tails[l]` 代表「長度為 `l+1` 的遞增子序列中，結尾元素的最小值」。

#### 為什麼要「替換成更小的結尾」？

```
思考：如果我有長度 3 的遞增子序列，結尾是 101
      現在又發現一個長度 3 的遞增子序列，結尾是 18

      18 < 101
      → 結尾 18 更容易接到更大的數字後面
      → 未來的潛力更高！
```

#### 狀態定義表

| 項目 | 內容 |
|------|------|
| 狀態 | tails[k] = 長度 k+1 的遞增子序列的最小結尾值 |
| 操作 | 對 x 二分搜第一個 >= x 的位置 pos |
| 若 pos==len(tails) | append（可以延伸出更長子序列） |
| 否則 | 替換 tails[pos]=x（保留未來彈性） |
| 答案 | len(tails) |

#### 程式碼解析

```python
def lis_bs(nums):
    tails = []
    for v in nums:
        lo, hi = 0, len(tails)
        while lo < hi:
            mid = (lo + hi) // 2
            if tails[mid] < v:
                lo = mid + 1
            else:
                hi = mid
        if lo == len(tails):
            tails.append(v)    # 延伸 LIS
        else:
            tails[lo] = v      # 替換成更小的結尾（保留未來的彈性）
    return len(tails)
```

#### 執行流程追蹤表

陣列：`[10, 9, 2, 5, 3, 7, 101, 18]`

| 處理 x | 處理前 tails | 二分搜 pos | 操作 | 處理後 tails | 動作說明 |
|--------|--------------|-----------|------|--------------|----------|
| 10 | [] | 0 | 追加 | [10] | 空表，直接加入 |
| 9 | [10] | 0 | 替換 | [9] | 9<10，結尾更小更好 |
| 2 | [9] | 0 | 替換 | [2] | 2<9，結尾更小更好 |
| 5 | [2] | 1 | 追加 | [2,5] | 5>2，延伸出長度2 |
| 3 | [2,5] | 1 | 替換 | [2,3] | 3<5，結尾更小更好 |
| 7 | [2,3] | 2 | 追加 | [2,3,7] | 7>3，延伸出長度3 |
| 101 | [2,3,7] | 3 | 追加 | [2,3,7,101] | 101>7，延伸出長度4 |
| 18 | [2,3,7,101] | 3 | 替換 | [2,3,7,18] | 18<101，結尾更小更好 |

答案：`len(tails) = 4`

#### 二分搜過程圖解（以 x=3, tails=[2,5] 為例）

```
tails = [2, 5]    找第一個 >= 3 的位置

  索引:   0    1
  值:     2    5
          ↑
        2 < 3 → 往右找 (lo=1)

  索引:   0    1
  值:     2    5
               ↑
             5 >= 3 → 找到！pos=1

替換：tails[1] = 3 → tails = [2, 3]
```

### 4-4 常見錯誤

❌ 誤以為 `tails` 就是答案序列
```text
tails=[2,3,7,18] 不代表 LIS 就是這四個數字，
它只是一個幫助計算長度的工具陣列
```
✅ `len(tails)` 才是 LIS 的長度；實際序列需要額外回溯

### 4-5 執行結果
```text
LIS (DP): 4
LIS (BS): 4
```

## 5. ex5_最長共同子序列.py

### 5-1 這支程式在做什麼？

**最長共同子序列（LCS，Longest Common Subsequence）**：給定兩個字串 A 和 B，找出兩者最長的共同子序列（不要求連續，只要前後順序相同）。

這支程式提供兩個版本：
- `lcs_length`：只計算長度，空間最佳化至 O(M)
- `lcs_string`：回傳實際的 LCS 字串，使用完整 2D 表格

### 5-2 核心觀念

$$
dp[i][j] = \begin{cases}
dp[i-1][j-1] + 1 & \text{若 } A[i-1] = B[j-1] \\
\max(dp[i-1][j],\ dp[i][j-1]) & \text{否則}
\end{cases}
$$

**白話解釋**：
- 若兩個字串的當前字元**相同**，LCS 長度在舊值基礎上 +1
- 若**不同**，取「去掉 A 末尾」或「去掉 B 末尾」兩種方案的較大值

#### 狀態定義表

| 項目 | 內容 |
|------|------|
| 狀態 | dp[i][j] = A[:i] 與 B[:j] 的 LCS 長度 |
| 轉移（相同） | dp[i][j] = dp[i-1][j-1] + 1 |
| 轉移（不同） | dp[i][j] = max(dp[i-1][j], dp[i][j-1]) |
| 初始 | dp[0][*] = 0, dp[*][0] = 0 |
| 答案 | dp[n][m] |

#### 依賴關係圖

```
dp[i][j] 依賴三個位置：
  dp[i-1][j-1]（左上角）  dp[i-1][j]（上方）
  dp[i][j-1]（左方）       dp[i][j]（要算的）

  相同字元 → 取左上角+1
  不同字元 → 取 max(上方, 左方)
```

### 5-3 程式碼解析（空間最佳化版）

```python
def lcs_length(A, B):
    n, m = len(A), len(B)
    dp = [0] * (m + 1)
    for i in range(1, n + 1):
        prev = 0             # 對應 dp[i-1][j-1]
        for j in range(1, m + 1):
            temp = dp[j]     # 暫存舊的 dp[j]，下一輪用作 prev
            if A[i - 1] == B[j - 1]:
                dp[j] = prev + 1
            else:
                dp[j] = max(dp[j], dp[j - 1])
            prev = temp
    return dp[m]
```

#### 變數對照表

| 1D 版變數 | 對應 2D 版位置 | 意義 |
|-----------|----------------|------|
| `dp[j]`（尚未覆蓋） | dp[i-1][j] | 上方（上一列的舊值） |
| `dp[j-1]`（已更新） | dp[i][j-1] | 左方（本列已更新的值） |
| `prev`（暫存的） | dp[i-1][j-1] | 左上角（對角線） |
| `temp` | dp[i-1][j] 舊值 | 暫存，下一輪變成 prev |

> 用一維陣列模擬二維表格，其中 `prev` 變數扮演「左上角 `dp[i-1][j-1]`」的角色。

### 5-4 執行流程

A = `"ABCBDAB"`，B = `"BDCAB"`

完整 2D 表格（`dp[i][j]` = A 前 i 個字元與 B 前 j 個字元的 LCS 長度）：

| | "" | B | D | C | A | B |
|---|-----|---|---|---|---|---|
| **""** | 0 | 0 | 0 | 0 | 0 | 0 |
| **A** | 0 | 0 | 0 | 0 | **1** | 1 |
| **B** | 0 | **1** | 1 | 1 | 1 | **2** |
| **C** | 0 | 1 | 1 | **2** | 2 | 2 |
| **B** | 0 | 1 | 1 | 2 | 2 | **3** |
| **D** | 0 | 1 | **2** | 2 | 2 | 3 |
| **A** | 0 | 1 | 2 | 2 | **3** | 3 |
| **B** | 0 | 1 | 2 | 2 | 3 | **4** |

答案：`dp[7][5] = 4`

#### 幾個關鍵格的計算

| 位置 | 比較 | 來源 | 值 |
|------|------|------|-----|
| dp[2][2] | B==B | 左上角 dp[1][1]+1 | 0+1=**1** |
| dp[4][2] | B==D? 否 | max(上 dp[3][2]=1, 左 dp[4][1]=1) | **1** |
| dp[5][3] | D==C? 否 | max(上 dp[4][3]=1, 左 dp[5][2]=2) | **2** |
| dp[7][5] | B==B | 左上角 dp[6][4]+1 | 3+1=**4** |

### 5-5 回溯找出實際 LCS 字串

```python
i, j = n, m
result = []
while i > 0 and j > 0:
    if A[i - 1] == B[j - 1]:
        result.append(A[i - 1])   # 這個字元是 LCS 的一部分
        i -= 1
        j -= 1
    elif dp[i - 1][j] > dp[i][j - 1]:
        i -= 1                    # 來自上方
    else:
        j -= 1                    # 來自左方
return ''.join(reversed(result))
```

#### 回溯規則表

| 情況 | 動作 | 意義 |
|------|------|------|
| A[i-1] == B[j-1] | 收集字元，往左上走 | 這個字元屬於 LCS |
| dp[i-1][j] > dp[i][j-1] | 往上走（i-=1） | 這個 dp 值來自上方，捨棄 A[i-1] |
| 否則 | 往左走（j-=1） | 這個 dp 值來自左方，捨棄 B[j-1] |

#### 回溯過程追蹤表

| 步驟 | 位置 (i,j) | 比較 | 動作 | 收集的字元 |
|------|-----------|------|------|-----------|
| 1 | (7,5) | A[6]=B == B[4]=B | 相同→取字元，往左上 | B |
| 2 | (6,4) | A[5]=A == B[3]=A | 相同→取字元，往左上 | A |
| 3 | (5,3) | A[4]=D vs B[2]=C | 不同→dp[4][3]=2 == dp[5][2]=2，往左 | |
| 4 | (5,2) | A[4]=D == B[1]=D | 相同→取字元，往左上 | D |
| 5 | (4,1) | A[3]=B == B[0]=B | 相同→取字元，往左上 | B |
| 6 | (3,0) | j=0 → 停止 | | |

收集順序：B → A → D → B，反轉後 = **BDAB**

### 5-6 常見錯誤

❌ 混淆「子序列」與「子字串（Substring）」
```text
A = "ABCDE"
B = "ACE"
子序列 LCS = "ACE"（不連續，但相對順序一致）✓
子字串 → "ACE" 必須連續出現在 A 中，這裡不符合
```
✅ LCS 允許跳格，只要前後順序一致就算

### 5-7 執行結果
```text
LCS 長度: 4
LCS 字串: BDAB
```

## 6. 五支程式共同學到的觀念

### 6-1 DP 與遞迴的差異

| 比較 | 遞迴 | DP |
|------|------|----|
| 重複計算 | 有（費氏數列 O(2^N)） | 無（記憶化，O(N)） |
| 思考方向 | 由上而下（Top-Down） | 由下而上（Bottom-Up） |
| 記憶體 | 呼叫堆疊 | dp 陣列 |
| 深度限制 | 有（遞迴深度） | 無 |

### 6-2 一維 DP vs 二維 DP

| 類型 | 典型題目 | 狀態設計 | 常見迴圈 |
|------|----------|----------|----------|
| 一維 DP | 爬樓梯、零錢、Kadane | `dp[i]` 只看當前位置 | 單迴圈 |
| 二維 DP | 背包、LCS | `dp[i][j]` 同時考慮兩個維度 | 雙迴圈 |

### 6-3 空間最佳化技巧

| 技巧 | 範例 | 效果 |
|------|------|------|
| 滾動變數 | 爬樓梯 `a, b = b, a+b` | O(N) → O(1) |
| 一維陣列 + 倒序 | 0/1 背包從後往前更新 | O(N×W) → O(W) |
| prev 變數 | LCS 空間壓縮中的 `dp[i-1][j-1]` 暫存 | O(N×M) → O(M) |

## 7. 常見陷阱與練習建議

### ❌ 常見錯誤

| 錯誤 | 後果 | 修正 |
|------|------|------|
| 忘記設定 `dp[0]` 或 `dp[0][0]` 初始值 | 所有值都是 0/INF，答案錯誤 | 先寫 base case |
| 0/1 背包用從前往後的迴圈 | 物品被重複選取（變無限背包） | 倒序更新 |
| Kadane 以 0 為初始值 | 全負數陣列回傳 0（錯） | 從 nums[0] 開始 |
| 混淆 LCS 與 Substring | 誤判題目要求 | 確認「是否允許跳格」 |
| LIS 的 tails 誤當成答案 | 輸出錯誤序列 | 只用 len(tails) |

### ✅ 建議練習

| # | 練習題 | 考驗的觀念 |
|---|--------|-----------|
| 1 | 爬樓梯改成「一次可走 1、2 或 3 步」 | 轉移方程式延伸 |
| 2 | 手動把零錢問題 dp 表填出來 | 追蹤 DP 表 |
| 3 | 找出「最大環形子陣列和」 | Kadane 變形 |
| 4 | 0/1 背包改成印出「選了哪些物品」 | 回溯技巧 |
| 5 | LCS 改成「最長共同子字串」 | 連續版 vs 跳格版 |

## 9. 總結

這五支程式讓你完整看到動態規劃從入門到中級的脈絡：

```text
爬樓梯（最基礎 DP：累加型）
   ↓
零錢問題（初次接觸「選或不選」的 DP）
   ↓
Kadane（以當前位置為「結尾」的 1D DP）
   ↓
0/1 背包（兩個維度的選擇 DP：倒序更新）
   ↓
LIS / LCS（子序列型 DP，邁向高級應用）
```

### 三句話記住這五題的精華

| 題目 | 一句話記法 |
|------|-----------|
| 爬樓梯 | dp[i] = dp[i-1] + dp[i-2]，兩個變數滾動就夠 |
| 零錢問題 | dp[i] = min(dp[i-c] + 1)，INF 當作「不知道」 |
| Kadane | 每個位置問：延續 or 重開？取大者 |
| 0/1 背包 | 倒序更新 = 每樣東西只能拿一次 |
| LIS/LCS | 子序列可跳格，tails 表拿來算長度最方便 |

> 動態規劃的本質是「找到問題的子結構，把子問題答案存起來，不重複計算」。
