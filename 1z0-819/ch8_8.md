### Question 1 — Thread.start() vs run()

```java
public class Test {
    public static void main(String[] args) {
        Thread t = new Thread(() -> System.out.print(Thread.currentThread().getName()));
        t.run();
    }
}
```

What is the result?

A. `Thread-0`  
B. `main`  
C. Compilation fails — lambda cannot be used with `Thread`  
D. An exception is thrown at runtime  
E. Nothing is printed

<details>
<summary>Answer</summary>
**B. `main`**

`t.run()` calls the `run()` method synchronously on the **current thread** (main). The new thread is never started.
</details>

### Question 2 — ExecutorService.submit() with Callable

```java
import java.util.concurrent.*;

public class Test {
    public static void main(String[] args) throws Exception {
        ExecutorService es = Executors.newSingleThreadExecutor();
        Future<Integer> f = es.submit(() -> 5 + 5);
        System.out.println(f.get());
        es.shutdown();
    }
}
```

What is the result?

A. `10`  
B. `55`  
C. Compilation fails — `submit()` does not accept lambda  
D. An `ExecutionException` is thrown  
E. The code compiles but waits indefinitely

<details>
<summary>Answer</summary>
**A. `10`**

`submit()` with a lambda returning a value is treated as `Callable<Integer>`. `f.get()` returns the result (`10`).
</details>

### Question 3 — AtomicInteger thread safety

```java
import java.util.concurrent.atomic.*;
import java.util.stream.*;

public class Test {
    static AtomicInteger counter = new AtomicInteger(0);

    public static void main(String[] args) {
        IntStream.range(0, 1000)
                 .parallel()
                 .forEach(i -> counter.incrementAndGet());
        System.out.println(counter.get());
    }
}
```

What is the result?

A. A number less than 1000  
B. `1000`  
C. A random number between 0 and 1000  
D. Compilation fails  
E. `0`

<details>
<summary>Answer</summary>
**B. `1000`**

`AtomicInteger.incrementAndGet()` is thread-safe. Even with a parallel stream, the result is guaranteed to be exactly 1000.
</details>

### Question 4 — deadlock scenario

```java
class Resource {
    synchronized void methodA(Resource other) {
        System.out.print("A ");
        other.methodB(this);
    }

    synchronized void methodB(Resource other) {
        System.out.print("B ");
    }
}

public class Test {
    public static void main(String[] args) {
        Resource r1 = new Resource();
        Resource r2 = new Resource();
        Thread t1 = new Thread(() -> r1.methodA(r2));
        Thread t2 = new Thread(() -> r2.methodA(r1));
        t1.start();
        t2.start();
    }
}
```

What is most likely to happen?

A. Prints `A B A B` then terminates  
B. Prints `A A` then deadlocks  
C. Prints nothing  
D. Compilation fails  
E. Prints `A B B A` then terminates

<details>
<summary>Answer</summary>
**B. Prints `A A` then deadlocks**

`t1` locks `r1` and calls `methodA`, then tries to lock `r2` in `methodB`. `t2` locks `r2` and calls `methodA`, then tries to lock `r1`. Circular wait → deadlock.
</details>

### Question 5 — synchronized method vs block

```java
public class Counter {
    private int count = 0;

    public synchronized void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}
```

If multiple threads call `increment()` and `getCount()` concurrently, which is true?

A. The code is thread-safe — `synchronized` ensures visibility and atomicity
B. `getCount()` may return stale values because it is not `synchronized`
C. `increment()` has a race condition despite `synchronized`
D. Compilation fails
E. An exception is thrown at runtime

<details>
<summary>Answer</summary>
**B. `getCount()` may return stale values because it is not `synchronized`**

`synchronized` on `increment()` provides mutual exclusion and visibility, but `getCount()` is not `synchronized`, so there is no happens-before guarantee. The read may see a stale value.
</details>

### Question 6 — Thread interruption

```java
public class Test {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            while (!Thread.currentThread().isInterrupted()) {
                // busy work
            }
            System.out.print("Interrupted ");
        });
        t.start();
        Thread.sleep(100);
        t.interrupt();
        t.join();
        System.out.print("Done");
    }
}
```

What is the result?

A. `Interrupted Done`  
B. `Done`  
C. Nothing — the thread never stops  
D. An `InterruptedException` is thrown  
E. Compilation fails

<details>
<summary>Answer</summary>
**A. `Interrupted Done`**

`t.interrupt()` sets the interrupt flag. The loop checks `isInterrupted()` and exits. The thread completes and `join()` returns. `"Interrupted Done"` is printed.
</details>

### Question 7 — Callable vs Runnable return value

```java
import java.util.concurrent.*;

public class Test {
    public static void main(String[] args) throws Exception {
        ExecutorService es = Executors.newSingleThreadExecutor();
        Future<?> f1 = es.submit(() -> System.out.print("A "));
        Future<Integer> f2 = es.submit(() -> 42);
        System.out.print(f1.get() + " ");
        System.out.println(f2.get());
        es.shutdown();
    }
}
```

What is the result?

A. `A null 42`  
B. `A 42`  
C. `A null`  
D. Compilation fails  
E. An exception is thrown

<details>
<summary>Answer</summary>
**A. `A null 42`**

`submit(Runnable)` returns `Future<?>`, and `.get()` returns `null` upon completion. `submit(Callable)` returns `Future<Integer>` with the result `42`.
</details>

### Question 8 — CompletableFuture

```java
import java.util.concurrent.*;

public class Test {
    public static void main(String[] args) throws Exception {
        CompletableFuture.supplyAsync(() -> "Hello")
                         .thenApply(s -> s + " World")
                         .thenAccept(System.out::print)
                         .join();
    }
}
```

What is the result?

A. `Hello World`  
B. `Hello`  
C. `World`  
D. Nothing is printed  
E. Compilation fails

<details>
<summary>Answer</summary>
**A. `Hello World`**

`supplyAsync` returns a `CompletableFuture<String>`. `thenApply` transforms the result. `thenAccept` consumes it. `join()` waits for completion.
</details>

### Question 9 — ConcurrentHashMap iteration

```java
import java.util.concurrent.*;

public class Test {
    public static void main(String[] args) {
        ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
        map.put("A", 1);
        map.put("B", 2);
        map.put("C", 3);

        for (String key : map.keySet()) {
            if (key.equals("B")) {
                map.remove(key);
            }
            System.out.print(key + " ");
        }
        System.out.println("| " + map.size());
    }
}
```

What is the result?

A. `A B C | 2`  
B. `A C | 2`  
C. A `ConcurrentModificationException` is thrown  
D. `A B C | 3`  
E. `A B | 2`

<details>
<summary>Answer</summary>
**A. `A B C | 2`**

`ConcurrentHashMap` iterators are weakly consistent — they reflect the state at the time of iteration and do NOT throw `ConcurrentModificationException`. The iterator sees all three keys. After removal, the map has 2 entries.
</details>

### Question 10 — ReentrantLock tryLock

```java
import java.util.concurrent.locks.*;

public class Test {
    static Lock lock = new ReentrantLock();

    public static void main(String[] args) {
        boolean acquired = lock.tryLock();
        System.out.print(acquired + " ");
        lock.unlock();
        acquired = lock.tryLock();
        System.out.println(acquired);
        lock.unlock();
    }
}
```

What is the result?

A. `true true`  
B. `false true`  
C. `true false`  
D. `false false`  
E. An `IllegalMonitorStateException` is thrown

<details>
<summary>Answer</summary>
**A. `true true`**

`tryLock()` acquires the lock if available. Both calls should succeed on the main thread sequentially since the lock is released between them.
</details>
