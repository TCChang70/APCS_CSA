### Question 1 — Covariant return types

```java
interface Animal {
    Object makeSound();
}

class Dog implements Animal {
    @Override
    public String makeSound() {
        return "Woof";
    }
}

class Puppy extends Dog {
    @Override
    public String makeSound() {
        return "Yip";
    }
}

public class Test {
    public static void main(String[] args) {
        Animal a = new Puppy();
        System.out.println(a.makeSound());
    }
}
```

What is the result?

A. `Woof`  
B. `Yip`  
C. Compilation fails — return type mismatch  
D. Compilation fails — `Puppy` cannot override `makeSound`  
E. `Object`

<details>
<summary>Answer</summary>
**B. `Yip`**

Covariant return types are allowed. `String` is a subtype of `Object`, `Puppy` overrides `Dog`. Runtime dispatch calls `Puppy.makeSound()` → `"Yip"`.
</details>

### Question 2 — Chained casts with var

```java
abstract class Ball {
    protected final int size;
    public Ball(int size) { this.size = size; }
}

interface Equipment {}

class SoccerBall extends Ball implements Equipment {
    public SoccerBall() { super(5); }
    public Ball get() { return this; }
}

public class Test {
    public static void main(String[] args) {
        var equipment = (Equipment) (Ball) new SoccerBall().get();
        System.out.print(((SoccerBall) equipment).size);
    }
}
```

What is the type of the variable `equipment`?

A. `SoccerBall`  
B. `Ball`  
C. `Equipment`  
D. `Object`  
E. Compilation fails

<details>
<summary>Answer</summary>
**C. `Equipment`**

`var` infers the type from the right-hand side. The final cast is `(Equipment)`, so `equipment` is of type `Equipment`.
</details>

### Question 3 — Overloading vs overriding resolution

```java
class Game {
    public void play(int x) {
        System.out.println("int");
    }
}

class BoardGame extends Game {
    public void play(Integer x) {
        System.out.println("Integer");
    }
}

public class Test {
    public static void main(String[] args) {
        Game g = new BoardGame();
        g.play(5);
    }
}
```

What is the result?

A. `int`  
B. `Integer`  
C. Compilation fails  
D. A `ClassCastException` is thrown at runtime  
E. None of the above

<details>
<summary>Answer</summary>
**A. `int`**

`play(Integer)` is an overload (not an override) in `BoardGame` — the parameter type is different. `g.play(5)` resolves at compile time using the reference type `Game`, calling `Game.play(int)`.
</details>

### Question 4 — Field hiding vs overriding

```java
class Parent {
    String value = "parent";
    String getValue() { return value; }
}

class Child extends Parent {
    String value = "child";
    String getValue() { return value; }
}

public class Test {
    public static void main(String[] args) {
        Parent p = new Child();
        System.out.print(p.value + " ");
        System.out.println(p.getValue());
    }
}
```

What is the result?

A. `parent child`  
B. `child child`  
C. `parent parent`  
D. `child parent`  
E. Compilation fails

<details>
<summary>Answer</summary>
**A. `parent child`**

Fields are accessed by reference type (`Parent` → `"parent"`). Methods use runtime dispatch (`Child.getValue()` → `"child"`).
</details>

### Question 5 — Constructor with this()

```java
class Person {
    String name;
    Person child;

    Person(String name, Person child) {
        this(name);
        this.child = child;
    }

    Person(String name) {
        this.name = name;
    }

    public String toString() { return name + " " + child; }
}

public class Test {
    public static void main(String[] args) {
        Person jane = new Person("Jane");
        Person john = new Person("John", jane);
        System.out.println(john);
    }
}
```

What is the result?

A. `John Jane`  
B. `John null`  
C. `Jane John`  
D. `John Person@...`  
E. `John`

<details>
<summary>Answer</summary>
**A. `John Jane`**

`new Person("John", jane)` calls `this("John")` → sets name to `"John"`, then sets `child = jane`. `toString()` prints `"John Jane"`.
</details>

### Question 6 — Constructor chaining with final fields

```java
public class Test {
    private final int x;

    public Test() {
        this(5);
    }

    public Test(int x) {
        this.x = x;
    }

    public static void main(String[] args) {
        Test t = new Test();
        System.out.println(t.x);
    }
}
```

What is the result?

A. `0`  
B. `5`  
C. Compilation fails — `x` might not be initialized  
D. Compilation fails — `this()` cannot be used with `final`  
E. `null`

<details>
<summary>Answer</summary>
**B. `5`**

The no-arg constructor calls `this(5)`, which assigns `x = 5`. Constructor chaining with `final` fields is valid as long as every constructor path initializes the field.
</details>

### Question 7 — Interface default method conflict

```java
interface A {
    default void show() {
        System.out.println("A");
    }
}

interface B {
    default void show() {
        System.out.println("B");
    }
}

public class Test implements A, B {
    public void show() {
        System.out.println("Test");
    }

    public static void main(String[] args) {
        A a = new Test();
        a.show();
    }
}
```

What is the result?

A. `A`  
B. `B`  
C. `Test`  
D. Compilation fails on class declaration  
E. Compilation fails on line `A a = new Test()`

<details>
<summary>Answer</summary>
**C. `Test`**

When two interfaces provide default methods with the same signature, the implementing class must override the method. Runtime dispatch calls `Test.show()`.
</details>

### Question 8 — Static method in enum

```java
enum Direction {
    NORTH, SOUTH, EAST, WEST;

    static Direction oppositeOf(Direction d) {
        switch (d) {
            case NORTH: return SOUTH;
            case SOUTH: return NORTH;
            case EAST:  return WEST;
            default:    return EAST;
        }
    }
}

public class Test {
    public static void main(String[] args) {
        System.out.println(Direction.oppositeOf(Direction.NORTH));
    }
}
```

What is the result?

A. `NORTH`  
B. `SOUTH`  
C. `EAST`  
D. `WEST`  
E. Compilation fails

<details>
<summary>Answer</summary>
**B. `SOUTH`**

Enum can have static methods. `oppositeOf(NORTH)` returns `SOUTH`. The method is called on the enum type directly.
</details>

### Question 9 — Interface member validity

Which are valid members of an interface? (Choose two)

A. `private void method();`  
B. `public static final int X = 10;`  
C. `protected void method();`  
D. `public default void method() { }`  
E. `final void method() { }`  
F. `private abstract void method();`

<details>
<summary>Answer</summary>
**B, D**

B: `public static final` is the default for interface fields — valid.  
D: `default` methods with a body are valid in Java 8+.  
A: `private` methods must have a body. C: `protected` is not allowed.  
E: `final` methods are not allowed in interfaces.  
F: `private` and `abstract` are contradictory.
</details>

### Question 10 — Abstract class and interface relationship

```java
interface Worker {
    void work();
}

abstract class Employee implements Worker {}

class Manager extends Employee {
    public void work() {
        System.out.println("Managing");
    }
}

public class Test {
    public static void main(String[] args) {
        Worker w = new Manager();
        w.work();
    }
}
```

What is the result?

A. `Managing`  
B. Compilation fails — `Employee` does not implement `work()`  
C. Compilation fails — `Manager` cannot extend `Employee`  
D. Compilation fails — `Worker w = new Manager()` is invalid  
E. Nothing is printed

<details>
<summary>Answer</summary>
**A. `Managing`**

An `abstract` class that `implements` an interface is not required to implement the interface methods. The first concrete class (`Manager`) must implement them.
</details>

### Question 11 — Garbage collection eligibility

```java
public class Test {
    String name;
    Test child;

    Test(String name) { this.name = name; }

    Test(String name, Test child) {
        this.name = name;
        this.child = child;
    }

    public static void main(String[] args) {
        Test a = new Test("A");
        Test b = new Test("B", a);
        Test c = new Test("C", b);
        a = null;
        b = null;
        // line 1
        c = null;
        // line 2
    }
}
```

At which point is the `Test("A")` object first eligible for garbage collection?

A. Immediately after `a = null`  
B. Immediately after `b = null`  
C. Immediately after `c = null`  
D. After `line 1`  
E. Never

<details>
<summary>Answer</summary>
**B. Immediately after `b = null`**

`Test("A")` is referenced by both `a` and `b.child`. After `a = null`, `b.child` still refers to it. After `b = null`, no references remain.
</details>

### Question 12 — static final initialization

```java
public class Test {
    static final int X;
    static final int Y = 10;

    static {
        X = 5;
    }

    public static void main(String[] args) {
        System.out.println(X + Y);
    }
}
```

What is the result?

A. `5`  
B. `10`  
C. `15`  
D. Compilation fails — `X` is not initialized  
E. Compilation fails — `static final` cannot be assigned in a static block

<details>
<summary>Answer</summary>
**C. `15`**

`static final` fields can be assigned in a `static` initializer block if not already assigned inline. `X = 5` in the static block, `Y = 10` inline. `5 + 10 = 15`.
</details>
