### Question 1 — InputStream vs Reader

Which statement correctly describes the difference between `InputStream` and `Reader` in Java I/O?

A. `InputStream` reads binary data; `Reader` reads character data  
B. `InputStream` reads character data; `Reader` reads binary data  
C. Both read binary data, but `Reader` is buffered  
D. `InputStream` is for output; `Reader` is for input  
E. There is no difference — they are interchangeable

<details>
<summary>Answer</summary>
**A. `InputStream` reads binary data; `Reader` reads character data**

`InputStream` and `OutputStream` work with bytes (binary data). `Reader` and `Writer` work with characters (text data), handling character encoding.
</details>

### Question 2 — Buffered streams

```java
import java.io.*;

public class Test {
    public static void main(String[] args) throws IOException {
        try (BufferedReader br = new BufferedReader(new FileReader("data.txt"))) {
            String line;
            while ((line = br.readLine()) != null) {
                System.out.println(line);
            }
        }
    }
}
```

What is the advantage of wrapping `FileReader` in `BufferedReader`?

A. It allows reading binary data from a text file  
B. It improves performance by reducing the number of file system reads  
C. It converts character encoding automatically  
D. It allows writing to the same file  
E. It compresses the file data during reading

<details>
<summary>Answer</summary>
**B. It improves performance by reducing the number of file system reads**

`BufferedReader` maintains an internal buffer, reducing the number of expensive file system I/O operations. It also provides the convenient `readLine()` method that `FileReader` does not have.
</details>

### Question 3 — transient keyword in serialization

```java
import java.io.*;

class Employee implements Serializable {
    String name;
    transient String password;
    static int count = 0;
}

public class Test {
    public static void main(String[] args) throws Exception {
        Employee e = new Employee();
        e.name = "Alice";
        e.password = "secret123";
        e.count = 5;

        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        ObjectOutputStream oos = new ObjectOutputStream(bos);
        oos.writeObject(e);
        oos.close();

        ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
        ObjectInputStream ois = new ObjectInputStream(bis);
        Employee deserialized = (Employee) ois.readObject();

        System.out.println(deserialized.name + " " + deserialized.password + " " + deserialized.count);
    }
}
```

What is the result?

A. `Alice secret123 5`  
B. `Alice null 5`  
C. `Alice null 0`  
D. `Alice secret123 0`  
E. Compilation fails

<details>
<summary>Answer</summary>
**C. `Alice null 0`**

`transient` fields are not serialized — `password` defaults to `null`. `static` fields are not serialized — `count` is reset to its default value `0` (since it was initialized inline to `0`, and no static initializer ran during deserialization).
</details>

### Question 4 — File.separator platform independence

Which is the correct platform-independent way to build a file path?

A. `"C:\\data\\config.properties"`  
B. `"C:/data/config.properties"`  
C. `"data" + File.separator + "config.properties"`  
D. `"data" + "/" + "config.properties"`  
E. `File.separator + "data" + File.separator + "config.properties"`

<details>
<summary>Answer</summary>
**C. `"data" + File.separator + "config.properties"`**

`File.separator` provides the platform-specific separator (`\` on Windows, `/` on other systems). Using it avoids hardcoded separators.
</details>

### Question 5 — try-with-resources and close order

```java
import java.io.*;

public class Test {
    public static void main(String[] args) throws IOException {
        try (FileOutputStream fos = new FileOutputStream("out.txt");
             BufferedOutputStream bos = new BufferedOutputStream(fos)) {
            bos.write("Hello".getBytes());
        }
    }
}
```

In which order are the resources closed?

A. `fos` first, then `bos`  
B. `bos` first, then `fos`  
C. Both are closed simultaneously  
D. The programmer must call `close()` explicitly  
E. The order is not guaranteed

<details>
<summary>Answer</summary>
**B. `bos` first, then `fos`**

Resources in try-with-resources are closed in the **reverse** order of their declaration. `bos` wraps `fos`, so it is important that `bos` is flushed and closed before `fos` is closed.
</details>

### Question 6 — Files.createTempFile

```java
import java.nio.file.*;

public class Test {
    public static void main(String[] args) throws IOException {
        Path p = Files.createTempFile("prefix_", ".tmp");
        System.out.println(p.getFileName());
    }
}
```

What is the result?

A. `prefix_.tmp`  
B. `prefix_<random>.tmp` (e.g., `prefix_123456789.tmp`)  
C. An `AccessDeniedException` is thrown  
D. `.tmp`  
E. Compilation fails

<details>
<summary>Answer</summary>
**B. `prefix_<random>.tmp` (e.g., `prefix_123456789.tmp`)**

`Files.createTempFile(prefix, suffix)` generates a unique random filename between the prefix and suffix. The file is created in the default temporary-file directory.
</details>

### Question 7 — File copy with Paths

```java
import java.nio.file.*;

public class Test {
    public static void main(String[] args) throws IOException {
        Path source = Paths.get("source.txt");
        Path target = Paths.get("target.txt");
        Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);
        System.out.println(Files.exists(target));
    }
}
```

What would happen if `target.txt` already exists and `REPLACE_EXISTING` is omitted?

A. The file is not copied and `false` is printed  
B. A `FileAlreadyExistsException` is thrown  
C. The file is overwritten regardless  
D. The program compiles but does nothing  
E. The source file is deleted

<details>
<summary>Answer</summary>
**B. A `FileAlreadyExistsException` is thrown**

Without `REPLACE_EXISTING`, `Files.copy()` throws `FileAlreadyExistsException` if the target file already exists.
</details>

### Question 8 — serialVersionUID

```java
import java.io.*;

class Account implements Serializable {
    private static final long serialVersionUID = 1L;
    String owner;
    double balance;
}

public class Test {
    public static void main(String[] args) throws Exception {
        Account a = new Account();
        a.owner = "John";
        a.balance = 1000.0;

        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        ObjectOutputStream oos = new ObjectOutputStream(bos);
        oos.writeObject(a);

        ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
        ObjectInputStream ois = new ObjectInputStream(bis);
        Account result = (Account) ois.readObject();
        System.out.println(result.owner + " " + result.balance);
    }
}
```

Why is `serialVersionUID` declared in a `Serializable` class?

A. To ensure the class is thread-safe  
B. To provide a version identifier for deserialization compatibility  
C. To specify the serialization format version  
D. To encrypt the serialized data  
E. To improve I/O performance

<details>
<summary>Answer</summary>
**B. To provide a version identifier for deserialization compatibility**

`serialVersionUID` is used during deserialization to verify that the sender and receiver have compatible versions of the class. If the UIDs don't match, an `InvalidClassException` is thrown.
</details>
