### Question 1 — Catch block matching order

```java
public class Test {
    public static void main(String[] args) {
        try {
            throw new ArithmeticException();
        } catch (RuntimeException e) {
            System.out.print("Runtime ");
        } catch (ArithmeticException e) {
            System.out.print("Arithmetic ");
        }
        System.out.print("Done");
    }
}
```

What is the result?

A. `Arithmetic Done`  
B. `Runtime Done`  
C. `Arithmetic Runtime Done`  
D. Compilation fails  
E. `Runtime Arithmetic Done`

<details>
<summary>Answer</summary>
**D. Compilation fails**

`ArithmeticException` is a subclass of `RuntimeException`. The `catch(ArithmeticException e)` block is unreachable because the more general `catch(RuntimeException e)` already catches it. This is a compilation error.
</details>

### Question 2 — Finally block and return

```java
public class Test {
    static int compute() {
        try {
            return 10;
        } finally {
            return 20;
        }
    }

    public static void main(String[] args) {
        System.out.println(compute());
    }
}
```

What is the result?

A. `10`  
B. `20`  
C. Compilation fails  
D. A runtime exception is thrown  
E. `10` followed by `20`

<details>
<summary>Answer</summary>
**B. `20`**

If a `finally` block has a `return` statement, it overrides any `return` value from the `try` block. The `finally` return value is what gets returned.
</details>

### Question 3 — try-with-resources suppressed exception

```java
class Resource1 implements AutoCloseable {
    public void close() throws Exception {
        throw new Exception("R1 close fail");
    }
}

class Resource2 implements AutoCloseable {
    public void close() throws Exception {
        throw new Exception("R2 close fail");
    }
}

public class Test {
    public static void main(String[] args) {
        try (Resource1 r1 = new Resource1();
             Resource2 r2 = new Resource2()) {
            throw new Exception("try block fail");
        } catch (Exception e) {
            System.out.println(e.getMessage());
            for (Throwable t : e.getSuppressed()) {
                System.out.println("Suppressed: " + t.getMessage());
            }
        }
    }
}
```

Which exception is the primary (caught) exception?

A. `R1 close fail`  
B. `R2 close fail`  
C. `try block fail`  
D. Any of the above — order is not deterministic  
E. Compilation fails

<details>
<summary>Answer</summary>
**C. `try block fail`**

In try-with-resources, the primary exception is the one thrown from the `try` block. Exceptions from `close()` methods are added as suppressed exceptions. Resources are closed in reverse order (R2 first, then R1).
</details>

### Question 4 — Checked exception handling

```java
import java.io.IOException;

public class Test {
    public static void main(String[] args) {
        try {
            method();
        } catch (IOException e) {
            System.out.println("IO");
        }
    }

    static void method() throws IOException {
        if (false) {
            throw new IOException();
        }
        throw new RuntimeException();
    }
}
```

What is the result?

A. `IO`  
B. A `RuntimeException` is thrown at runtime  
C. Compilation fails — the `catch` block is unreachable  
D. Compilation fails — `IOException` is never thrown in the try block  
E. Nothing is printed

<details>
<summary>Answer</summary>
**B. A `RuntimeException` is thrown at runtime**

`method()` declares `throws IOException`, so the compiler is satisfied. The `throw new RuntimeException()` executes because `if(false)` is never true. Since `RuntimeException` is unchecked, it propagates up uncaught.
</details>

### Question 5 — Multi-catch syntax

```java
public class Test {
    public static void main(String[] args) {
        try {
            int[] a = new int[5];
            int x = a[10];
        } catch (ArrayIndexOutOfBoundsException | NullPointerException e) {
            System.out.println("A");
        } catch (IndexOutOfBoundsException e) {
            System.out.println("B");
        }
    }
}
```

What is the result?

A. `A`  
B. `B`  
C. Compilation fails — `IndexOutOfBoundsException` is a supertype  
D. Compilation fails — multi-catch syntax error  
E. `A` followed by `B`

<details>
<summary>Answer</summary>
**A. `A`**

`ArrayIndexOutOfBoundsException` is caught by the first multi-catch block. The code compiles because `ArrayIndexOutOfBoundsException` and `NullPointerException` are unrelated types.
</details>

### Question 6 — Exception propagation in method chain

```java
class CustomException extends Exception {
    CustomException(String msg) { super(msg); }
}

public class Test {
    static void a() throws CustomException {
        b();
    }

    static void b() throws CustomException {
        c();
    }

    static void c() throws CustomException {
        throw new CustomException("error in c");
    }

    public static void main(String[] args) {
        try {
            a();
        } catch (CustomException e) {
            System.out.println(e.getMessage());
        }
    }
}
```

What is the result?

A. `error in c`  
B. Compilation fails — exceptions must be caught at each level  
C. The stack trace is printed  
D. Nothing is printed  
E. The code compiles but throws an exception at runtime

<details>
<summary>Answer</summary>
**A. `error in c`**

Checked exceptions declared with `throws` propagate up the call stack until caught. `main()` catches `CustomException` and prints its message.
</details>

### Question 7 — RuntimeException in finally

```java
public class Test {
    public static void main(String[] args) {
        try {
            throw new RuntimeException("try");
        } catch (RuntimeException e) {
            throw new RuntimeException("catch");
        } finally {
            throw new RuntimeException("finally");
        }
    }
}
```

What exception is thrown to the caller?

A. `RuntimeException: try`  
B. `RuntimeException: catch`  
C. `RuntimeException: finally`  
D. Both `catch` and `finally` exceptions — the `catch` is suppressed  
E. The code does not compile

<details>
<summary>Answer</summary>
**C. `RuntimeException: finally`**

The `finally` block always executes. If it throws an exception, that exception replaces any exception thrown in `try` or `catch`. The original exception is lost.
</details>

### Question 8 — Instance field mutation before exception

```java
public class Test {
    int x = 10;

    void process() {
        try {
            x = 20;
            throw new Exception();
        } catch (Exception e) {
            System.out.print(x + " ");
        } finally {
            System.out.print(x);
        }
    }

    public static void main(String[] args) {
        new Test().process();
    }
}
```

What is the result?

A. `10 10`  
B. `10 20`  
C. `20 20`  
D. `20 10`  
E. Compilation fails

<details>
<summary>Answer</summary>
**C. `20 20`**

Despite the exception being thrown, `x = 20` was already executed. The `catch` block accesses the mutated field (`20`), and `finally` also sees `20`.
</details>

### Question 9 — Optional and NoSuchElementException

```java
import java.util.Optional;

public class Test {
    static Optional<String> lookup(int id) {
        if (id > 0) {
            return Optional.of("Found");
        }
        return Optional.empty();
    }

    public static void main(String[] args) {
        String result = lookup(-1).orElse("Default");
        System.out.println(result);
    }
}
```

What is the result?

A. `Found`  
B. `Default`  
C. A `NoSuchElementException` is thrown  
D. `null`  
E. `Optional.empty`

<details>
<summary>Answer</summary>
**B. `Default`**

`lookup(-1)` returns `Optional.empty()`. `orElse("Default")` returns the fallback value `"Default"`. Safe alternative to `.get()`.
</details>

### Question 10 — Method overriding and exception declaration

```java
import java.io.IOException;
import java.io.FileNotFoundException;

class Parent {
    void process() throws IOException {
        System.out.println("Parent");
    }
}

class Child extends Parent {
    @Override
    void process() throws FileNotFoundException {
        System.out.println("Child");
    }
}

public class Test {
    public static void main(String[] args) {
        Parent p = new Child();
        try {
            p.process();
        } catch (IOException e) {
            System.out.println("Caught");
        }
    }
}
```

What is the result?

A. `Child`  
B. `Parent`  
C. `Child Caught`  
D. Compilation fails — `Child.process()` throws narrower exception  
E. Compilation fails — `Child.process()` throws broader exception

<details>
<summary>Answer</summary>
**A. `Child`**

An overriding method can declare the same exception, a narrower exception, or no exception at all. `FileNotFoundException` is a subclass of `IOException`, so this is valid. Runtime dispatch calls `Child.process()`.
</details>
