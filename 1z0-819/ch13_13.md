### Question 1 — Retention policy

```java
import java.lang.annotation.*;

@Retention(RetentionPolicy.CLASS)
@Target(ElementType.METHOD)
public @interface Loggable {}
```

Which statement is true?

A. The annotation is retained in the source code only  
B. The annotation is retained in the class file but not available at runtime  
C. The annotation is available at runtime via reflection  
D. The annotation can be applied to classes  
E. The annotation can be applied to fields

<details>
<summary>Answer</summary>
**B. The annotation is retained in the class file but not available at runtime**

`RetentionPolicy.CLASS` means the annotation is recorded in the `.class` file but discarded by the JVM at runtime. `SOURCE` → source only. `RUNTIME` → available via reflection.
</details>

### Question 2 — @Target multiple types

```java
import java.lang.annotation.*;

@Target({ElementType.FIELD, ElementType.PARAMETER})
public @interface Valid {}
```

Where can `@Valid` be applied?

A. On methods and classes  
B. On fields and parameters only  
C. On any element  
D. On constructors and local variables  
E. On type parameters only

<details>
<summary>Answer</summary>
**B. On fields and parameters only**

The `@Target` annotation restricts where the annotation can be used. `@Valid` can be applied to fields (`FIELD`) and method/constructor parameters (`PARAMETER`).
</details>

### Question 3 — @Inherited

```java
import java.lang.annotation.*;

@Inherited
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface Entity {}

@Entity
class Base {}

class Derived extends Base {}
```

Which expression returns `true`?

A. `Derived.class.isAnnotationPresent(Entity.class)`  
B. `Base.class.getDeclaredAnnotation(Entity.class) != null`  
C. `Derived.class.getDeclaredAnnotations().length > 0`  
D. `Base.class.getAnnotations().length == 0`  
E. `Derived.class.getAnnotation(Entity.class) == null`

<details>
<summary>Answer</summary>
**A. `Derived.class.isAnnotationPresent(Entity.class)`**

`@Inherited` causes the annotation to be inherited by subclasses. `isAnnotationPresent()` checks inherited annotations. `getDeclaredAnnotation()` does not look at superclass annotations.
</details>

### Question 4 — Annotation with default

```java
public @interface Config {
    String value() default "dev";
    int timeout() default 30;
}
```

Which usage is **not** valid?

A. `@Config`  
B. `@Config(timeout = 60)`  
C. `@Config("prod")`  
D. `@Config(value = "prod", timeout = 60)`  
E. `@Config(timeout = 60, "prod")`

<details>
<summary>Answer</summary>
**E. `@Config(timeout = 60, "prod")`**

When using multiple annotation elements, each must be specified by name using the `name = value` syntax. Positional arguments are only allowed when there is a single element named `value`.
</details>

### Question 5 — @Repeatable

```java
import java.lang.annotation.*;

@Repeatable(Schedules.class)
@interface Schedule {
    String day();
}

@interface Schedules {
    Schedule[] value();
}
```

Which code compiles?

A. `@Schedule(day = "Mon")` on a single method  
B. `@Schedule(day = "Mon") @Schedule(day = "Tue")` on a single method  
C. `@Schedules({@Schedule(day = "Mon"), @Schedule(day = "Tue")})` on a method  
D. A and C  
E. A, B, and C

<details>
<summary>Answer</summary>
**E. A, B, and C**

`@Repeatable` allows multiple annotations of the same type on a single element without wrapping them in a container annotation. All three forms are valid.
</details>

### Question 6 — Annotation type valid members

Which is a valid member type inside an `@interface` declaration?

A. `String value();`  
B. `int[] values();`  
C. `Class<?> type();`  
D. `SomeEnum mode();`  
E. All of the above

<details>
<summary>Answer</summary>
**E. All of the above**

Annotation members can return primitives, `String`, `Class`, enums, annotations, and arrays of any of these types.
</details>

### Question 7 — @SuppressWarnings for raw types

```java
import java.util.*;

public class Test {
    @SuppressWarnings("rawtypes")
    public static void main(String[] args) {
        List list = new ArrayList();  // raw type
        list.add("hello");
    }
}
```

Which warning is suppressed?

A. Unchecked cast warning  
B. Rawtypes warning  
C. Deprecation warning  
D. All warnings  
E. Serial warning

<details>
<summary>Answer</summary>
**B. Rawtypes warning**

`@SuppressWarnings("rawtypes")` suppresses warnings about using generic types without type parameters. `"unchecked"` would be needed to suppress unchecked cast warnings.
</details>

### Question 8 — Deprecated(forRemoval)

```java
public class Test {
    @Deprecated(forRemoval = true, since = "9")
    public void oldMethod() {}

    public static void main(String[] args) {
        new Test().oldMethod();
    }
}
```

How does `forRemoval = true` differ from a regular `@Deprecated`?

A. The code will not compile  
B. The annotation indicates the API is scheduled for removal in a future release  
C. `since` is ignored when `forRemoval` is `true`  
D. The compiler produces an error instead of a warning  
E. There is no difference

<details>
<summary>Answer</summary>
**B. The annotation indicates the API is scheduled for removal in a future release**

`forRemoval = true` adds an extra level of severity — it signals intent to remove the API. The compiler produces a stronger warning (often with a different message) than regular deprecation.
</details>
