### Question 1 — module-info.java location

Where must `module-info.java` be placed in a module?

A. In the package root directory  
B. In the source root directory (same level as packages)  
C. In the `META-INF` directory  
D. In the same directory as the main class  
E. Anywhere in the source tree — the compiler finds it automatically

<details>
<summary>Answer</summary>
**B. In the source root directory (same level as packages)**

`module-info.java` must be placed at the root of the source directory, not inside any package.
</details>

### Question 2 — exports vs opens

```java
module com.example.core {
    exports com.example.core.api;
    opens com.example.core.internal;
}
```

Which statement is true?

A. Both `api` and `internal` packages can be accessed via reflection from other modules.  
B. Only `api` can be accessed via reflection; `internal` is not accessible at all.  
C. Only `internal` can be accessed via reflection; `api` can be used at compile and runtime.  
D. Both packages are accessible at compile time.  
E. Compilation fails — `opens` requires `exports`.

<details>
<summary>Answer</summary>
**C. Only `internal` can be accessed via reflection; `api` can be used at compile and runtime.**

`exports` makes the package available at compile and runtime. `opens` only allows reflective access at runtime, not compile-time access.
</details>

### Question 3 — requires transitive

```java
module com.framework {
    exports com.framework.core;
    requires transitive com.logging;
}
```

If module `com.app` `requires com.framework`, which statement is true?

A. `com.app` can access `com.logging` without explicitly requiring it.  
B. `com.app` must also `requires com.logging` to access it.  
C. `com.app` can access `com.framework.core` only.  
D. `com.framework` re-exports `com.logging` to all modules unconditionally.  
E. The code does not compile — `transitive` is not a valid keyword.

<details>
<summary>Answer</summary>
**A. `com.app` can access `com.logging` without explicitly requiring it.**

`requires transitive` means any module that `requires com.framework` implicitly also reads `com.logging`. This is commonly used for SPI dependencies.
</details>

### Question 4 — ServiceLoader: provides and uses

Given:

```java
// module payment.spi
module payment.spi {
    exports com.payment.spi;
}

// module payment.impl
module payment.impl {
    requires payment.spi;
    provides com.payment.spi.PaymentGateway
        with com.payment.impl.PaypalGateway;
}

// module payment.app
module payment.app {
    requires payment.spi;
    uses com.payment.spi.PaymentGateway;
}
```

Which module contains the service provider interface declaration?

A. `payment.spi`  
B. `payment.impl`  
C. `payment.app`  
D. `payment.spi` and `payment.impl`  
E. `payment.app` and `payment.impl`

<details>
<summary>Answer</summary>
**A. `payment.spi`**

`com.payment.spi.PaymentGateway` is the service provider interface (SPI) — declared in `payment.spi`. `payment.impl` provides an implementation. `payment.app` consumes the service via `ServiceLoader`.
</details>

### Question 5 — Module directives

How many of the following are valid directives in `module-info.java`?

- `exports`  
- `imports`  
- `requires`  
- `provides`  
- `uses`  
- `transitive`  
- `opens`

A. 3  
B. 4  
C. 5  
D. 6  
E. 7

<details>
<summary>Answer</summary>
**D. 6**

Valid directives: `exports`, `requires`, `provides`, `uses`, `transitive`, `opens` — all are valid. `transitive` can be used with `requires`. Only `imports` is NOT a valid module directive.
</details>

### Question 6 — Exports to specific modules

```java
module com.library {
    exports com.library.api;
    exports com.library.internal to com.partner;
}
```

Which statement is true about `com.library.internal`?

A. All modules can access it at compile time.  
B. Only `com.partner` can access it at compile time.  
C. No module can access it at compile time.  
D. `com.partner` can access it, but only via reflection.  
E. The `exports...to` syntax is invalid.

<details>
<summary>Answer</summary>
**B. Only `com.partner` can access it at compile time.**

`exports ... to` is a qualified export — only the specified module(s) can access the package. Other modules cannot access `com.library.internal`.
</details>

### Question 7 — jdeps tool

What does the `jdeps` tool do?

A. Creates a new module  
B. Analyzes class dependencies and recommends module directives  
C. Packages a module into a JAR file  
D. Compiles all module source files  
E. Runs the module and shows execution trace

<details>
<summary>Answer</summary>
**B. Analyzes class dependencies and recommends module directives**

`jdeps` (Java Dependency Analyzer) analyzes class files and dependencies, helping to create `module-info.java` by showing which packages are required and which should be exported.
</details>

### Question 8 — java.base implicit dependency

Which statement about `java.base` is false?

A. Every module implicitly requires `java.base`.  
B. `java.base` contains `java.lang`, `java.util`, `java.io`, and other core packages.  
C. `java.base` must be explicitly listed in every `module-info.java`.  
D. The `requires mandated java.base` output can be seen with `jdeps`.  
E. `java.base` exports packages to all modules.

<details>
<summary>Answer</summary>
**C. `java.base` must be explicitly listed in every `module-info.java`.**

`java.base` is automatically required by all modules — it does NOT need to be declared explicitly in `module-info.java`. All other statements are true.
</details>
